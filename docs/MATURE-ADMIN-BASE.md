# Phase 1.1 前端重建原则：成熟代码作为母体，不再补丁式设计

## 核心决定

商家后台前端不再以现有 `AdminPanel / Editor / StoreWorkspace` 为母体继续修补。

新的实现方式：

1. **直接以成熟开源商家后台代码为母体。**
2. **先迁移成熟项目已有页面和交互，再把本项目 API、权限、成本和差异化能力接进去。**
3. 同一能力同时存在“成熟项目版本”和“本项目旧版本”时，必须逐项比较后只保留更好的一个，不维护两套。
4. 不允许为了“保持旧代码”而牺牲成熟体验。

## 首选前端母体

### Open Shop 微信小程序模板商家后台

仓库：`jamezzh7/open-shop-wechat-template`
许可证：MIT
技术：React 19 + Vite + TypeScript，和本项目兼容度高。

优先直接迁移/改造：

- `admin-web/src/components/Layout.tsx`：侧边栏、主内容区、退出入口；
- `admin-web/src/App.tsx`：路由结构；
- `admin-web/src/pages/Dashboard.tsx`：商家仪表板结构；
- `admin-web/src/pages/Products.tsx`：分类/商品/SKU 管理页面结构；
- `admin-web/src/pages/Orders.tsx`：订单页面结构（当前只接占位/后续真实 API，不伪造数据）；
- `admin-web/src/pages/Shipping.tsx`：配送/自提设置页面结构；
- `admin-web/src/index.css`：成熟商家后台基础视觉风格。

CloudBase 数据层、认证层和存储层不照搬；改接本项目 NestJS API。

### Refine + Ant Design

许可证：MIT。

用于补足通用后台基础能力（数据资源、CRUD、表单、表格、通知、加载/错误、权限等），但**不得为了框架而重新设计已成熟的 Open Shop 页面**。如果 Open Shop 已有更直观页面，优先保留其商家交互，仅替换底层数据调用/通用组件。

## “谁更好就留谁”的强制比较

### 图片上传

Open Shop：

- 优点：界面流程简单，已经有选择图片、上传、预览；
- 缺点：直接浏览器上传 CloudBase，文件路径使用时间戳+原文件名，缺少本项目当前已有的服务端 MIME/签名/解码/重编码/租户归属校验。

本项目 PR #17：

- 优点：服务端校验 MIME/扩展名/文件签名、sharp 解码并重编码 WebP、路径由 UUID 生成、租户隔离、StorageAdapter 可替换 COS/OSS；
- 缺点：前端页面体验不成熟。

**决定：使用 Open Shop 的成熟上传交互/页面位置，保留本项目 PR #17 的安全上传后端。不要保留旧的自制商品页面。**

### 后台布局/导航

Open Shop 已有完整侧边栏、路由和独立页面。

**决定：直接迁移其布局和路由结构，舍弃旧的一页式 AdminPanel/StoreWorkspace 导航壳。**

### 商品页面

Open Shop 已有分类、商品、SKU、搜索、编辑弹窗、图片等完整结构。

**决定：以其页面为母体，把字段和 API 映射到本项目 Product/Variant/Category；再加入本项目“默认规格、人民币精确转换、图片安全接口”等能力。旧 ProductManager/通用 Editor 不作为母体继续扩展。**

### 门店、成本、经营分析

成熟母体缺少本项目差异化能力。

**决定：在成熟侧边栏和页面风格中新增本项目页面；复用成熟表单/卡片/表格组件，业务逻辑保留本项目实现。**

## 必须保留的本项目能力

- Merchant → Brand → Store 租户隔离；
- 金额整数分与精确元/分转换；
- PR #17 的媒体资产表、StorageAdapter 和安全图片处理；
- 门店软删除/历史保留（权限需继续审查）；
- 默认规格事务；
- Phase 1 成本模型、历史采购、BOM、成本快照；
- 现有集成测试和数据库约束。

## 必须退役/删除的旧前端基础层

当成熟母体迁移完成且测试覆盖后，应删除或停止使用：

- 旧 `AdminPanel` 页面壳；
- 旧通用 `Editor` 作为整个后台的主表单框架；
- 旧 `StoreWorkspace` 一页式导航/功能堆叠；
- 与成熟母体重复的 ProductManager、通用 CRUD UI；
- 任何已经被成熟页面替代的临时布局。

不得长期同时维护新旧两套后台。

## 验收标准

人工打开后台时必须明显看到“成熟商家系统”的结构，而不是旧界面加了几个新按钮：

- 左侧固定导航；
- 独立路由页面；
- 首页经营概览；
- 成熟商品管理页；
- 门店设置页；
- 库存页；
- 配送页；
- 经营分析页；
- 统一弹窗、表单、表格、空状态、加载状态、错误提示；
- 中文、人话、人民币元。

本轮不进入 Phase 2。成熟后台基础层未完成人工试用前，不合并。
