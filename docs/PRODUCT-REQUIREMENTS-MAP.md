## 推荐后续顺序与维护规则

1. 当前库存 PR 及 #26/#27 分别人工审查；任何合并都另需明确授权。
2. 修复基础管理遗留：选项组编辑/归档、孤立媒体安全回收、员工与设备授权、成本/定价历史界面、真实统计口径；独立小 PR，避免顺手重写核心。
3. 人工批准 Phase 4 后实现独立顾客认证与小程序 Mock 闭环；再接真实支付、配送沙箱并验签/幂等/对账，不能先对外营业。
4. 真实数据足够后做会员/券/统计、脱敏导出、规则助手；经营计划确认/暂停/重研判先做可靠状态和审计，再按需接 AI。
5. 最后逐步验证增长实验和非糖水模板，不提前引入重型设施。

后续每个功能 PR 应同步更新对应行：状态、性质、代码/API/模型、最新可复核测试证据、缺项及依赖。测试只证明其断言范围；组件测试不替代真实浏览器，Mock 不替代平台接入，API 已有不代表界面完成。
