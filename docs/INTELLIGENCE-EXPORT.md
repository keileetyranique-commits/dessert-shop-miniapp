# 智能研判与数据导出设计（v0.1）

## 1. 目标

系统提供两条并行能力：

### 路线 A：系统内置智能研判
系统自动识别：
- 热门商品
- 冷门商品
- 高利润商品
- 高销量低利润商品
- 高复购商品
- 新客偏好商品
- 老客偏好商品
- 时间段偏好
- 天气/季节相关趋势（后续可选接入）
- 配送距离对商品转化的影响
- 优惠券对商品销量和利润的影响
- 商品组合与加购关系

并给出可解释建议，例如：
- 建议主推
- 建议降价/提价
- 建议参加活动
- 建议停止活动
- 建议调整包装
- 建议下架观察
- 建议与某商品组合销售
- 建议针对老客/新客投放

### 路线 B：导出给 ChatGPT 分析
后台允许导出脱敏后的分析数据包，用户可直接上传给 ChatGPT 做更深入研判。

支持导出：
- CSV
- XLSX
- JSON
- ZIP 分析包

导出内容可选：
- 商品销量
- 销售额
- 毛利/贡献利润
- 全成本利润
- 复购率
- 新客/老客购买结构
- 时段销量
- 配送距离
- 优惠使用情况
- 加料偏好
- 退款/取消
- 库存与售罄
- 商品评价（如后续接入）
- 订单明细（脱敏）
- 会员分群（脱敏）

## 2. MVP 原则

第一版不直接上“黑盒 AI 推荐模型”。

先实现：
1. 规则引擎
2. 统计分析
3. 趋势分析
4. 可解释评分
5. 推荐理由

后续再预留 AI/LLM 或机器学习模型接口。

## 3. 商品智能评分

每个商品形成多个维度分数：

- 销量分
- 销售额分
- 贡献利润分
- 全成本利润分
- 复购分
- 新客吸引力分
- 优惠依赖度
- 退款/取消风险分
- 配送适配分
- 库存稳定分

示例：

```text
综合热度分 =
销量 30%
+ 销售额 20%
+ 复购率 20%
+ 新客购买率 10%
+ 加购率 10%
+ 最近增长率 10%
```

权重由后台配置。

## 4. 分类标签

系统自动打标签：

- 爆款
- 潜力款
- 高利润款
- 引流款
- 复购款
- 低销量高利润
- 高销量低利润
- 优惠依赖款
- 配送敏感款
- 冷门款
- 亏损风险款
- 建议观察
- 建议下架

标签必须显示“为什么”。

例如：

> 高销量低利润  
> 近 30 天销量排名第 2，但贡献利润率只有 8%，主要原因是平均优惠 ¥4.2 + 平均配送补贴 ¥3.1。

## 5. 用户偏好分析

不依赖敏感个人信息，仅基于店内消费行为：

- 喜欢的品类
- 甜度偏好（若商品规格包含）
- 温/冰偏好
- 加料偏好
- 客单价区间
- 常下单时间
- 常点商品
- 常见搭配
- 对优惠敏感度
- 配送距离区间

形成匿名/会员级推荐画像。

## 6. 推荐系统

### 顾客端推荐
- 猜你喜欢
- 常点商品
- 与当前商品常一起购买
- 当前时段热销
- 老客回购推荐
- 新客入门推荐
- 高性价比推荐

### 商家端推荐
- 今日建议主推
- 本周潜力商品
- 利润过低预警
- 建议提价商品
- 建议降促销强度商品
- 建议组合销售
- 建议淘汰/观察

## 7. 可解释性

任何建议都必须包含：

- 使用的数据周期
- 核心指标
- 触发规则
- 建议原因
- 预估影响（如可计算）
- 置信度/数据量提示

示例：

> 建议主推：红豆双皮奶  
> 原因：近 14 天复购率 31%，高于门店均值 12 个百分点；贡献利润率 34%；晚间 20:00–22:00 转化率最高。  
> 数据量：86 单  
> 建议：晚间首页置顶，并尝试 2 元加料套餐。

## 8. 数据不足保护

新店/新品不能强行给出结论。

当样本不足时：

> 当前样本量不足，暂不建议自动调整价格或上下架。

后台可设置最小样本量，例如：
- 至少 30 单
- 至少 14 天
- 至少 20 个独立用户

## 9. 导出给 ChatGPT

后台新增：

**数据中心 → 导出分析包**

支持选择：
- 日期范围
- 门店
- 商品
- 用户分群
- 是否包含订单明细
- 是否包含成本
- 是否包含优惠
- 是否包含配送
- 导出格式

默认生成：

```text
analysis-export/
  summary.csv
  products.csv
  orders.csv
  customer_segments.csv
  promotions.csv
  delivery.csv
  costs.csv
  README.txt
  schema.json
```

README.txt 自动说明字段定义，方便直接上传给 ChatGPT。

## 10. 隐私与脱敏

导出时默认：
- 不导出姓名
- 不导出手机号
- 不导出 OpenID
- 不导出精确地址
- 地址只保留距离、行政区或网格级信息
- 用户使用匿名 customer_id
- 可选不导出单笔明细，仅导出聚合数据

## 14. 第一版验收标准

1. 能识别热销/冷门/高利润/低利润高销量商品。
2. 每个标签都有明确原因。
3. 能按 7 天 / 30 天查看趋势。
4. 能按新客/老客拆分商品偏好。
5. 能识别常见商品组合。

9. 导出包有字段说明文件。
10. 样本量不足时不乱给结论。


## 15. 首页智能研判卡片与“计划执行”工作流

智能研判必须出现在**商家后台首页第一屏**，不是藏在数据中心二级菜单。

首页卡片至少展示：

- 今日/近 7 天/近 30 天关键趋势
- 今日建议主推商品
- 潜力商品
- 冷门/低利润预警
- 优惠异常
- 配送成本异常
- 当前待确认的“经营计划”
- 最近一次研判时间
- 使用的数据范围和样本量

### 15.1 研判 → 计划 → 人工确认

系统自动研判后，不得直接擅自修改商品价格、优惠、首页排序或上下架。

流程：

```text
新数据进入
→ 系统研判
→ 生成建议
→ 生成“待确认计划”
→ 老板查看
→ [同意执行] / [修改计划] / [暂不执行]
```

只有点击 **“同意执行”** 后，系统才按计划执行允许自动化的动作。

### 15.2 计划状态

每个智能计划拥有明确状态：

- DRAFT：系统生成草案
- PENDING_APPROVAL：等待老板确认
- APPROVED：已同意，等待/正在执行
- RUNNING：执行中
- PAUSED：已暂停
- NEEDS_REVIEW：新数据导致原计划需要重新研判
- COMPLETED：计划完成
- CANCELLED：老板取消
- SUPERSEDED：被新计划替代

### 15.3 计划暂停按钮

首页和计划详情页必须有明显的：

**暂停计划**

点击后：

1. 立即停止尚未执行的自动动作。
2. 已完成的动作不自动回滚，除非该动作支持明确的安全回滚。
3. 记录暂停人、暂停时间和暂停原因（原因可选）。
4. 页面显示“计划已暂停，不会继续执行”。
5. 新数据仍可以继续收集。

### 15.4 用新数据重新研判

计划暂停后提供：

**使用最新数据重新研判**

流程：

```text
PAUSED
→ 锁定旧计划版本
→ 读取最新销售/利润/配送/优惠/库存数据
→ 重新计算
→ 生成新计划版本
→ 显示新旧计划差异
→ 等待老板再次点击“同意执行”
```

旧计划不得被直接覆盖，必须保留版本历史。

### 15.5 新旧计划对比

重新研判后展示：

- 哪些建议没变
- 哪些建议被取消
- 哪些建议新增
- 哪些商品的优先级改变
- 原因是什么
- 使用的数据周期变化
- 指标变化
- 对利润/销量的预估变化

示例：

> 旧计划：晚间主推杨枝甘露  
> 新计划：暂停主推杨枝甘露，改推红豆双皮奶  
> 原因：最近 7 天芒果成本上涨 18%，杨枝甘露贡献利润率从 31% 降到 16%；红豆双皮奶复购率上升至 34%。

### 15.6 允许自动执行的动作

MVP 中即使老板点击“同意执行”，也只允许执行**低风险、可追踪**动作，例如：

- 调整后台“推荐位”
- 标记主推商品
- 创建待发布营销草稿
- 生成优惠方案草稿
- 调整智能推荐排序
- 设置商品观察标签

高风险动作必须二次确认，不允许静默自动执行：

- 修改正式售价
- 大额优惠
- 商品下架
- 删除商品
- 修改配送补贴上限
- 修改最低利润线

### 15.7 新数据触发重新研判

支持两种模式：

- 手动：老板点击“重新研判”
- 自动：达到条件后生成新的“待确认计划”，但**不自动覆盖正在执行的计划**

触发条件可配置：

- 每天固定时间
- 累计新增 N 单
- 商品成本变化超过 X%
- 某商品利润率变化超过 X%
- 配送费均值变化超过 X%
- 退款/取消异常
- 新品达到最小样本量

如果已有 RUNNING 计划，新研判只创建候选版本并提醒老板：

> 检测到新数据，现有计划可能需要调整。请查看新研判结果。

### 15.8 首页交互建议

首页顶部智能卡片：

```text
智能经营助手
最近研判：19:30
数据范围：近 14 天 / 326 单

[今日建议 3 条] [风险预警 2 条]

当前计划：晚间甜品主推计划
状态：执行中

[查看计划] [暂停计划] [重新研判]
```

待确认时：

```text
新计划待确认
预计影响：客单价 +¥1.8（参考）
置信度：中
[查看详情] [同意执行] [修改] [暂不执行]
```

所有“预计影响”必须标注为估算，不得当成保证结果。
