# Phase 1.1：商家后台易用性与本地化重构

关联 Issue #16；从 main `013aea5` 创建 `phase-1-1-merchant-ux`。不包含 Phase 2。

## 商家操作

- 创建门店只必填名称；地址、电话和营业时间放入“选填”。系统默认北京时间、营业中。创建成功刷新列表并选中新门店。
- 首页、商品、库存、经营分析、门店设置分层。订单、营销、配送仅标明规划，不能操作。复杂配方、包装、固定成本和快照放入经营分析。
- 商品页提供搜索、分类筛选、分页、状态标签、空状态和加载状态。新增路径为名称→分类→售价→图片→保存，事务内自动建立默认规格。原有多规格接口保留在高级设置。
- 表单分为必填、推荐图片、默认折叠的选填、系统自动。内部状态、单位和损耗率用中文和百分比显示。
- 金额输入元，显示 ¥18.80；字符串拆分配合 BigInt 转成整数分，包括每分钟人工费率。拒绝空值、负数、科学计数法、超过两位小数及超出数据库整数范围的值。零成本与未配置不混同。
- OWNER 可在门店设置中归档，必须再次输入门店名称。后台设置 deletedAt 和 INACTIVE，历史数据保留。归档后切换其他门店，没有门店则进入创建提示。

## 接口变更

所有门店接口要求现有 Bearer 凭据及 X-Store-Id；服务端验证商户、品牌、门店与角色。生产和测试使用同一授权逻辑。

| 方法与路径（前缀 /api/v1/admin） | 行为                                                  | 权限               |
| -------------------------------- | ----------------------------------------------------- | ------------------ |
| DELETE /store                    | JSON confirmationName 必须与当前名称一致；软归档      | OWNER              |
| POST /products/simple            | 原商品字段及整数 salePriceFen，原子创建商品和默认规格 | OWNER、MANAGER     |
| POST /media                      | multipart/form-data 单一 file；返回 id 与 imageUrl    | OWNER、MANAGER     |
| GET /media/:id                   | 读取当前授权门店图片，禁止跨门店引用                  | 当前门店已授权角色 |

现有商品接口继续支持多规格。新图片必须使用本店上传记录；已有外部图片地址可以原样保留、显示或移除，但不能新增外部地址。旧地址在浏览器直接读取，不携带后台凭据，也不由服务器代理。

客户端不再无条件读取 JSON：空成功响应返回无数据；门店创建在空响应时通过刷新列表识别唯一新增门店；无法确认时提示刷新确认，避免盲目重复创建。非 JSON、网络中断和服务端异常均转换为中文提示。

## 图片安全与存储

复用 Ant Design 拖拽上传、选择、进度条及 sharp 解码重编码。支持 JPG/PNG/WebP，最大 5 MiB，最多 2000 万像素，限制单帧，输出长边不超过 2400 像素的 WebP，去除元数据和非图像尾部内容。扩展名、MIME、签名和解码结果必须一致。

拒绝空文件、危险或多重扩展名、路径分隔符、控制字符和超长文件名。实际保存名由服务端 UUID 生成。StorageAdapter 提供 put/get/remove，LocalStorage 校验完整 UUID 分层路径，禁止目录穿越。数据库记录同时保存 Merchant/Brand/Store 归属，通过复合外键保证一致。下载通过鉴权接口，无公共静态目录，响应禁止内容嗅探和缓存。

本地存储目录由服务端 UPLOAD_DIR 环境变量配置，默认 ./data/uploads。Docker Compose 使用 uploads_data 持久卷。未来接 COS/OSS 仅替换适配器；商品领域不包含云厂商字段或凭据。

“移除图片”清空商品引用，保存商品后生效；不物理删除历史文件。取消编辑或替换图片可能留下未引用资产；自动清理与配额管理列入后续运维工作。生产应备份数据库及上传卷；不要以 docker compose down -v 作为日常停机方式。

## 数据库与启动

新增 migration `202609190003_merchant_ux`，仅增加 media_assets、租户复合外键、唯一存储键、租户查询索引与大小 CHECK。Store 已有 deletedAt，不需要重建门店表；未修改旧 migration。

安装 Node.js >=22.12、pnpm 10.15.0，启动 Docker Desktop 后运行 `pnpm dev`。打开 http://localhost:5173，按 [Phase 1 登录说明](PHASE-1.md) 使用本机环境中的凭据。首次初始化和迁移由现有启动脚本完成。

完整命令：pnpm install --frozen-lockfile、pnpm db:generate、pnpm lint、pnpm format:check、pnpm typecheck、pnpm test、pnpm build、pnpm db:migrate（连续两次）、pnpm test:integration。工作流 checks 在真实 PostgreSQL/Redis 上运行迁移和集成测试；compose 验证一键启动和服务探测。

新增测试覆盖：创建及自动选择门店、空响应、非 JSON 错误和中文提示、归档二次确认及切换、上传交互进度/预览/移除、图片安全校验、角色和跨租户拒绝、归档门店不可再操作、默认规格、精确金额、百分比及中文单位。沿用 Phase 0/1 全部测试，集成场景使用生产授权配置。

## 本轮边界与后续审查

- 登录仍采用 Phase 1 访问凭据；人员账号和自助登录不在本轮。
- 本轮没有商品图片公开访问接口。未来消费者端需要单独设计授权或受控公开发布。
- 未实现对象存储适配器、未引用文件清理、存储配额；当前使用可替换本地适配器。
- 长期商品数量增长后可追加服务端分页；当前表格筛选分页基于原有全量列表 API。
- 不实现 Pricing Engine、真实订单、支付、配送及 AI；等待人工审查。

构建观察：当前后台 JavaScript 约 986 KB（gzip 约 317 KB），有默认包大小提示。后续可评估按经营分析页面延迟加载，不在本轮为消除提示强行迁移框架。
