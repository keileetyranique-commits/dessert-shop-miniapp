# litemall 原版成熟基座（Issue #19）

## 本轮交付边界

本轮整体迁入并独立运行 litemall，不把 Vue 重写成 React，不把 Java API 改成 NestJS，不重做商品、分类、删除或图片交互。现有 React 后台仅作 legacy/reference，现有租户隔离、整数分、成本/BOM、权限和图片安全实现全部保留。

分支 `phase-1-1-litemall-baseline` 从 `phase-1-1-mature-admin-shell` 的 `94f158f9a85a4e54114925c6c3b17f0f8a6e555f` 创建。PR #18 保持 Draft，不修改、不合并。新 PR 以该分支为比较基线，避免重复展示 PR #18 的代码。

## Docker 启动和访问

只需现有 Node.js 和 Docker Desktop，不需要本机 Java、Maven、MySQL、Vue 2 工具链。在仓库根目录执行：

```sh
node deploy/litemall/setup.mjs
docker compose --env-file deploy/litemall/.env -f deploy/litemall/compose.yml up -d --build
node deploy/litemall/smoke.mjs
```

后台地址：**http://localhost:18080/#/login**。

登录账号和随机密码分别在 **`deploy/litemall/.env` 的 `BASELINE_ADMIN_USER`、`BASELINE_ADMIN_PASSWORD`**。文件已忽略，不提交 Git、不打进镜像、不打印日志。初始化会替换所有上游示例管理员密码，主管理员为 `baseline-admin`；以后启动保留管理员在后台修改的密码。若已在后台改密，自动冒烟脚本的本地密码也需同步。

停止（保留数据）：

```sh
docker compose --env-file deploy/litemall/.env -f deploy/litemall/compose.yml down
```

启动后不自动删除数据卷。端口占用时改 `.env` 的 `BASELINE_PORT` 后重建容器；本地上传图片地址也使用此端口。请保持用 localhost 访问。

构建在容器内使用 Node 16/Vue CLI、Maven/Java 8，运行 Java 8 + MySQL 8。镜像来自 Docker Hub 官方 library 的公共缓存 `mirror.gcr.io/library`，避免本机 Docker Hub 授权域名连接失败。前端 API 基址只通过构建环境设为 `/admin`，使用原应用同源静态资源服务，不改页面。依赖锁保存在部署目录，不修改上游 package.json。

## 数据和运行隔离

- Compose 项目名 `litemall-upstream-baseline`，专属 network、`mysql_data`、`media_data` 卷。
- MySQL 数据库名 `litemall_baseline`，不映射数据库端口；Nginx 入口仅绑定 `127.0.0.1:18080`，将请求转发给隔离网络内的原版服务。Java/MySQL 不接入入口外网网络。
- 不挂载现有 Postgres、Redis、媒体卷，不读取现有业务 `.env`；没有更改 Prisma schema/migration。
- 初始化只导入上游 `litemall_table.sql`、`litemall_data.sql`。**不执行**带有 DROP DATABASE、固定账号密码的 `litemall_schema.sql`。
- 原版样例商品/会员等为上游演示数据，不能视作本项目真实经营数据。
- 运行网络为 internal，禁止容器向外连接；短信、邮件、物流查询关闭；初始化使用原版系统配置关闭微信分享码生成。真实微信登录、支付、退款、物流、云存储不在此环境启用。
- 初始化脚本仅设置开发管理员凭据与分享码配置，额外创建一张初始化标记表；不修改商品/分类/订单业务实现。
- 原版金额是 MySQL DECIMAL/Java BigDecimal，并非本项目整数 Fen；原版权限是 Shiro 角色权限，并非 Merchant → Brand → Store。本轮按 Issue 要求独立保留，不能连接生产数据或声称已经完成多租户适配。

## 原版人工验收步骤

### 商品新增、编辑、删除

1. 使用本地环境凭据登录，进入 **商品管理 → 商品列表**，确认原版搜索、筛选、表格、编辑、删除入口可见。
2. 点击添加/商品上架，填写唯一商品编号、商品名称，选择分类；按需填写简介、图片、详细介绍。
3. 保留原版单规格或建立多规格，在货品区域编辑价格与库存后确认；点击页面底部上架。回商品列表按名称查找，应看到刚创建的商品。
4. 点击该行编辑，修改名称、简介或原版允许的货品字段，保存后重新查询并打开详情确认。
5. 仅删除自己创建的验收商品，按原版页面提示操作，再次查询应不再显示。删除交互保持固定 SHA 原样，本轮未新增确认框或重写按钮。
6. 图片上传使用原版 Element UI 上传和 Java 本地存储；取消选择、预览、更换等保持上游行为，不使用 PR #18 的 React ImageEditor。

### 分类新增、编辑、删除

1. 进入 **商场管理 → 商品类目**，点击添加，填写独特名称，选择一级类目并填写所需说明后确定。
2. 在新分类行点击编辑，改名后确定，再次打开确认已持久化。
3. 可按原版流程建立二级类目并选择父类目，确认层级显示。
4. 删除本次创建的二级、一级分类，确认列表不再显示；不要删除要继续测试的商品正在使用的分类。

## 验证入口和已知限制

`verify.mjs` 校验来源完整性；`smoke.mjs` 使用独立环境随机凭据，验证真实数据库 CRUD 并只清理自身命名记录。独立 GitHub Actions `litemall-baseline` 执行来源校验、Docker 构建/启动和冒烟；原 `checks`、`compose` 继续验证已有成果。

上游 Maven 默认跳过单元测试，其部分旧测试依赖外部服务；不能将镜像构建声称为上游全部测试通过。此任务以新增的真实本地系统冒烟验收补充。上游前端构建存在通知页 `rmNotice` 未导出及包体积告警，原样记录，不趁本轮改写通知功能。Vue 2/Java 8 基座为开发审查环境，版本升级和安全加固另行审查。

当前不迁移现有经营数据，不合并任何 PR，不进入 Pricing Engine/AI，完成后等待当前会话人工审查。
