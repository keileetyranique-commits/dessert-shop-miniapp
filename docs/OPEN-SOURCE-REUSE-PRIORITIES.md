# 优先复用的成熟开源模块清单

> 目的：避免 Codex 和人工开发把时间、算力、维护成本浪费在已经成熟的通用能力上。
>
> 本清单是“优先搜索和复用顺序”，不是要求把整个项目替换成第三方框架。任何引入都必须先验证许可证、维护状态、依赖兼容性、安全影响和迁移成本。

## 一、总规则

开发任何“通用商家能力”前，按下面顺序处理：

1. 先看本清单中的成熟项目。
2. 再搜索同类、近期维护、许可证清晰的开源实现。
3. 能直接复用成熟组件/模式，就不要从零重写。
4. 若第三方项目技术栈与本项目冲突，优先复用交互、信息架构、局部无耦合组件，不强行换掉后端或整个前端框架。
5. 明确 MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause 等可商用许可证后，才允许直接复制/改造代码。
6. GPL/AGPL、双重商业许可、许可证缺失或不明确的项目，默认只研究思路，不复制代码。
7. 任何实际复制或改造的第三方代码，都要在 `docs/OPEN-SOURCE-REUSE.md` 记录来源、许可证、文件范围和修改内容。

## 二、当前项目技术约束

当前商家后台是 React 19 + Vite + TypeScript 的轻量实现，尚未绑定大型后台框架。

因此本阶段优先级是：

- 先复用成熟 UI/页面模式和局部组件；
- 不为了“看起来成熟”一次性重写整个 admin-web；
- 只有当引入成熟框架能明显减少后续总代码量和维护成本时，才允许替换现有基础层；
- 任何框架迁移必须单独说明收益、风险、迁移量和回退方案。

## 六、明确暂不采用的项目类型

### GPL / AGPL / 商业双许可

例如某些成熟电商系统虽然功能很强，但许可证可能要求衍生代码遵循强 copyleft，或需要商业许可。

处理原则：

- 可以研究架构和用户流程；
- 默认不复制其源码；
- 如未来确实值得采用，必须单独做许可证评估后再决定。

### 许可证不明项目

即使功能非常好，也只能：

- 看思路；
- 看页面结构；
- 看业务流程；

不能复制代码。

## 七、按模块的优先顺序

### 商家后台基础框架

1. zuiidea/antd-admin
2. ant-design/ant-design-pro
3. marmelab/react-admin
4. saleor/saleor-dashboard

### 商品管理

1. saleor/saleor-dashboard（成熟商品后台交互）
2. jamezzh7/open-shop-wechat-template（餐饮/微信业务适配）
3. zuiidea/antd-admin（通用表单和 CRUD）

### 商品图片上传

优先使用成熟组件/模式，不自造上传控件。

需要满足：

- 拖拽/点击；
- 预览；
- 上传进度；
- 替换；
- 删除；
- 中文错误提示；
- 文件类型和大小限制；
- 服务端 MIME/文件签名二次校验。

具体存储仍通过本项目 Storage Adapter，第三方 UI 不决定后端存储方案。

### 门店/商品表单

优先参考：

1. Ant Design Pro 的分层表单；
2. antd-admin 的 CRUD；
3. Saleor Dashboard 的商品编辑信息层级。

必须按照本项目规则简化为：

- 必填；
- 选填；
- 系统自动；
- 高级设置。

### 商家后台导航

业务目标：

首页｜商品｜订单｜库存｜营销｜配送｜经营分析｜门店设置

优先参考成熟后台的信息架构，但最终以普通餐饮店老板的使用频率为准。

### 微信小程序菜单/购物车

1. jamezzh7/open-shop-wechat-template
2. 其他许可证明确的原生微信点餐项目
3. 无许可证项目只参考交互，不复制代码

### 订单后台/POS

进入 Phase 3 时重新专项搜索。

重点复用：

- 订单列表；
- 状态流展示；
- 新订单弹窗；
- 声音提醒；
- 快捷操作；
- 移动/平板响应式。

订单状态机、幂等、权限和测试模式仍由本项目自研。

### 图表/经营分析

图表组件优先直接使用成熟图表库，不自己绘制图表引擎。

但：

- 指标计算由本项目后端完成；
- AI 不直接算确定性利润；
- 商家默认看到简单趋势图/对比图，不堆专业 BI。

- 原料和经营风险雷达；

## 九、Codex 每次复用前必须报告

编码前：

- 找到了哪些候选成熟项目；
- 每个项目的许可证；
- 哪个项目与当前技术栈最接近；
- 准备直接复用什么；
- 准备只参考什么；
- 哪些仍然必须自研。

编码后：

- 实际复制/改造了哪些文件或组件；
- 来源仓库和原文件；
- 许可证；
- 做了哪些修改；
- 是否新增依赖；
- 对 bundle、服务器、数据库和安全的影响；
- 为什么没有选择其他成熟实现。

目标不是“用了越多第三方越好”，而是：

> **成熟通用能力少花钱，核心差异化能力集中投入。**
