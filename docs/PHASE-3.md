# Phase 3：订单、接单工作台与故障测试中心

依据 Issue #4 最新完整规格，基线为 main 的 `c7970c29cf94f6e7a92235c40c59541c13030e82`，分支为 `phase-3-orders-pos-test-center`。保留 C 后台与 Phase 2 定价引擎。仅服务端授权测试交易；等待 Draft PR 人工审查，不合并、不进入 Phase 4。

## 启动和操作

1. 启动 Docker Desktop，运行 `pnpm dev`。
2. 可选准备专用演示门店：`docker compose exec -T api node scripts/seed-order-demo.mjs`。只允许 development 数据库、服务端测试开关和已配置老板身份；不改其他门店，不自动下单，再运行不重置已有库存和策略。
3. 测试中心：<http://localhost:5173/admin/order-test>；订单：<http://localhost:5173/admin/orders>；POS：<http://localhost:5174>。
4. 分别使用本地 `.env` 的 `ADMIN_IDENTITIES` 已配置 token 登录，选择“Phase 3 流程验收门店”。凭据只留页面内存，不提交、不写进报告。
5. POS 点击“开启接单声音”。测试中心选择真实商品/选项、数量、履约方式，加入购物车并结算。补差必须显式同意。
6. 提交、模拟付款，在 POS 接单制作、出餐叫号、自取/堂食取餐，或发配送、骑手接单、送达。
7. 故障中心可触发付款失败、重复付款、网络重试、并发抢库存、骑手失败、超时、报价上涨、重新询价、老板异常退款。按钮调用真实服务端，拒绝不合法状态。

演示夹具明确确认无原料和单品包装、单份其他成本 ¥3.00、当月固定成本为零、选项成本 ¥0.50。这只是测试数据，不代表真实门店。月份变化可重新运行脚本补当月资料；真实门店缺资料始终阻断。

订单页使用 C 外壳和 Ant Design 表格、分页、搜索、状态筛选、详情抽屉、事件和快捷操作。测试中心包含真实购物车、故障结果和老板结算设置（自动接单、包装、优惠券、满减）。POS 复用同一订单及鉴权组件。参考 Open Shop 固定 SHA 的订单交互，未复制业务源码；完整来源见 OPEN-SOURCE-REUSE.md。

## 状态、库存、利润保护

订单、支付、履约、库存预占分开建模。待付款→待接单→制作→待取餐/配送→完成；取消为终态。串行化事务锁订单和规格，创建与预占原子提交，冲突有限重试。完成扣库存；付款失败、拒单、超时、取消释放；无限库存不扣数量。原库存接口不得调至预占量以下，有预占不能切换库存模式。

复用内部 readPricing，服务端读取商品、启用选项组、成本、规则、费用和有效报价。客户端不传最终金额或风险结论。预览、创建、付款、接单、发配送重新校验；缺资料、停售、库存不足、无规则、过期报价、利润不足均阻断。自动接单必须老板授权且逐单通过。

同键同请求返回同一结果；键冲突拒绝。重复付款/送达及并发操作不重复扣返库存。成交金额、明细和事件不可变；重新询价只更新运行时报价引用。模拟报价上涨阻断后，可恢复正常模拟报价再验证，或由老板终止尚未交付的异常测试订单并重下。已配送/完成不可使用恢复取消返还库存。

每十秒扫描最多 100 笔待付款/待接单超时订单；重启从数据库恢复。过期一天的预览及未被订单引用的报价分批清理。历史订单证据不自动删除；真实上线前需另定归档周期，Phase 2 模拟历史保留策略另记后续。

## API 和安全

所有新接口带 `/api/v1/admin` 前缀，使用 Bearer 和 X-Store-Id，同时验证非生产、服务端测试开关、角色和 Merchant→Brand→Store。生产/TEST_MODE=false 逐接口拒绝；生产误开测试模式直接启动失败。

| 接口                                   | 用途                            |
| -------------------------------------- | ------------------------------- |
| GET /orders/menu                       | 可售规格和启用选项，不含成本    |
| GET /orders/packaging                  | 本店整单包装名称/编号，不含成本 |
| GET/PUT /orders/settings               | 查看/老板确认结算配置           |
| POST /orders/preview                   | 2 分钟有效的结算预览            |
| POST /orders                           | 幂等创建并预占，显式补差确认    |
| GET /orders、/orders/:id               | 分页列表、详情和事件            |
| POST /orders/:id/actions               | 合法状态迁移                    |
| POST /order-test/quotes                | 15 分钟有效模拟配送报价         |
| POST /order-test/quotes/:id/invalidate | 本人本店报价失效                |
| POST /order-test/orders/:id/requote    | 幂等上涨/重新询价               |
| POST /order-test/orders/:id/timeout    | 超时关闭和库存补偿              |

## 明确限制

没有真实支付退款、配送平台、公开顾客认证或 Phase 4 小程序。POS 为前台 5 秒有限轮询，不是后台推送；后台标签可能被节流。每次提醒检查最近 50 单，长时间离线应在订单列表分页核对。自定义铃声最大 1 MB、30 秒，仅存设备；需先点击开启声音，真实扬声器效果待用户确认。后台/POS 构建有大包体积提示，未增加额外基础设施。
