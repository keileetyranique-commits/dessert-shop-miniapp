# 增长、行为设计与一键经营建议（v0.1）

## 1. 目标

系统不仅完成“点单”，还要帮助商家提升：

- 下单转化率
- 客单价
- 复购率
- 加购率
- 优惠使用效率
- 活动利润
- 老客召回率

所有增长功能遵循三个原则：

1. **不欺骗用户**：禁止虚假倒计时、虚假库存、暗扣费用、默认勾选付费项。
2. **先算利润再做优惠**：任何营销方案必须经过利润保护引擎。
3. **建议可解释、可一键实施、可暂停、可回滚/终止**。

## 2. 小程序端行为设计

### 2.1 首页排序

优先展示：
- 当前时段热销
- 高复购商品
- 新客友好商品
- 高利润且高转化商品
- 店铺主推商品

首页避免一次展示过多 SKU，支持：
- 推荐区
- 热销区
- 新品区
- 常点区
- 套餐区

### 2.2 选择架构

减少用户决策疲劳：

- 默认展示“推荐规格”，但不能默认附加收费加料
- 规格数量过多时折叠低频选项
- 对高复购组合提供“常用搭配”
- 对首次购买用户显示“第一次点可以试试”

### 2.3 加购

支持基于真实订单数据给出：
- 常一起购买
- 加 ¥X 升级套餐
- 再加 ¥X 达免配送/满减门槛
- 高利润加料推荐

任何“凑单”提示必须显示真实门槛和真实差额。

### 2.4 社会证明

可以显示真实数据：
- 近 7 天热销
- 本周回购较高
- 店内人气榜

不得伪造“已有 999 人购买”等数据。

### 2.5 稀缺与库存

仅在真实库存不足时显示：
- 今日剩余少量
- 某配料售罄

不得制造虚假稀缺。

### 2.6 复购

订单完成后支持：
- 再来一单
- 收藏常点
- 下次可用券
- 合理时机的召回提醒

避免过度打扰；频率后台可配置。

## 3. 优惠策略引擎

系统预置策略模板：

### 新客
- 首单立减
- 首单满减
- 首单免/减配送费
- 新人套餐

### 老客
- N 天未下单召回券
- 第 N 单奖励
- 常购商品专属券
- 会员积分抵扣

### 提升客单价
- 满 X 减 Y
- 满 X 免/减配送
- 套餐价
- 加价购

### 清库存
- 临近售罄/当天备料剩余的限时真实优惠
- 指定商品组合优惠

### 低峰时段
- 指定时段优惠
- 指定时段配送补贴

## 4. 优惠推荐器

每次推荐优惠时必须计算：

- 预计增加订单量
- 预计客单价变化
- 预计优惠成本
- 预计配送补贴变化
- 预计贡献利润
- 预计全成本利润
- 盈亏临界点

输出：

```text
建议：满 39 减 5
适用：新客
预计影响：客单价 +¥6.2（估算）
预计贡献利润率：24%
风险：3km 以上订单可能触发配送补差
[查看依据] [一键生成活动] [修改参数]
```

“一键生成活动”只生成待确认活动草稿。
正式发布前二次确认。

## 5. 实验系统 A/B Test

后台支持对以下内容做实验：

- 首页排序
- 商品主图
- 商品名称
- 套餐展示
- 满减门槛
- 优惠券面额
- 推荐位
- 加购文案

记录：
- 曝光
- 点击
- 加购
- 下单
- 支付
- 客单价
- 贡献利润
- 复购

实验不得只看转化率，必须同时看利润。

## 6. 一键实施

智能研判生成经营建议后，后台提供：

- 一键生成首页推荐方案
- 一键生成优惠草稿
- 一键生成套餐草稿
- 一键调整推荐排序
- 一键建立 A/B 实验

所有动作进入计划系统：
PENDING_APPROVAL → APPROVED → RUNNING

可随时暂停。

## 7. 风险保护

以下情况禁止自动发布：
- 预计贡献利润低于底线
- 优惠与免配送叠加后亏损
- 样本量不足
- 活动可能导致库存压力
- 活动折扣超过老板设置上限
- 新用户价格与老用户差异超出配置范围

## 8. 商家首页增长卡片

首页显示：

- 今日转化漏斗
- 加购率
- 客单价
- 复购率
- 优惠成本
- 活动利润
- 当前 A/B 实验
- 智能增长建议

示例：

> 近 7 天有 19% 用户在差 ¥3–¥8 达到免配送时放弃结算。  
> 建议测试“满 35 减 3”与“满 39 减配送费”的两组方案。  
> 系统预计后者利润更稳。
