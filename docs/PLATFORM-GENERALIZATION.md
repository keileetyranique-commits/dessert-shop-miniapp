# 通用门店平台化设计（v0.1）

## 1. 目标

系统从第一版起避免写死为“糖水店”。

糖水店是首个业务模板，但底层应可复用到：
- 饮品店
- 咖啡店
- 烘焙店
- 快餐店
- 熟食店
- 鲜花店
- 水果店
- 零售小店
- 其他本地配送/自取门店

## 2. 核心抽象

底层统一使用：

- Business / Merchant：商户
- Store：门店
- Catalog：商品目录
- Product：商品
- Variant / SKU：规格
- Modifier：加料/附加项/选项
- Inventory：库存
- Fulfillment：履约方式
- Promotion：促销
- Customer：客户
- Order：订单
- Delivery：配送
- Pricing：价格与利润
- Insight：经营研判

禁止在核心领域代码中写死：
- 糖水
- 甜度
- 冰量
- 杯
- 碗

这些应通过“行业模板 + 自定义属性”实现。

## 3. 行业模板

### 糖水/饮品模板
可预设：
- 甜度
- 温度
- 冰量
- 加料
- 杯型

### 烘焙模板
可预设：
- 尺寸
- 口味
- 生日牌
- 预约时间

### 零售模板
可预设：
- 单位
- 条码
- 多规格库存

模板仅提供默认配置，不影响底层数据模型。

## 4. 自定义字段

后台支持为商品/订单/门店配置自定义字段：

- 文本
- 数字
- 单选
- 多选
- 布尔
- 日期
- 金额

例如：
- 饮品：甜度
- 鲜花：祝福语
- 蛋糕：蜡烛数量
- 零售：包装方式

## 5. 模块化

能力模块可开关：

- 配送
- 自取
- 堂食
- 预约
- 库存
- 会员
- 积分
- 优惠券
- 成本中心
- 智能研判
- A/B 实验
- 骑手比价

不同商户可启用不同模块。

## 6. 品牌与主题

支持：
- 店名
- Logo
- 主题色
- 首页模块顺序
- Banner
- 推荐模块
- 文案
- 联系方式

避免前端写死糖水店视觉。

## 7. 扩展接口

适配器模式：
- PaymentProvider
- DeliveryProvider
- NotificationProvider
- StorageProvider
- AnalyticsProvider

策略模式：
- PricingStrategy
- PromotionStrategy
- RecommendationStrategy
- FulfillmentStrategy

## 8. 数据隔离

从第一版支持 merchant_id / store_id 维度。

未来可以：
- 一个老板多品牌
- 一个品牌多门店
- 不同行业共用系统

任何查询必须显式带租户范围，防止跨商户数据泄露。

## 9. 版本与迁移

- 数据库迁移必须可重复部署
- API 使用版本前缀
- 配置需有 schema_version
- 新功能默认通过 feature flag 开启
- 不允许用一次性硬编码破坏已有门店

## 10. 插件化预留

后续可增加：
- 新配送平台
- 新支付渠道
- 新报表
- 新行业模板
- 新推荐算法
- 新营销策略

无需重写订单核心。
