# dessert-shop-miniapp

微信糖水店私域点单系统（顾客小程序 + 商家后台 + 接单工作台 + 配送比价 + 成本/智能定价 + 可关闭测试模式）。

## 项目目标

让顾客通过自有微信小程序完成点单、支付、配送与会员沉淀，减少对外卖平台抽佣的依赖，并在下单前自动判断配送距离、配送成本和订单利润，避免“免配送费但越卖越亏”。

同时为商家提供完整成本核算和参考定价能力，把食材、包装、人工、房租、水电、优惠券、支付手续费和骑手配送等成本纳入分析。

## 第一阶段范围

- 顾客微信小程序
  - 商品分类、规格、加料、购物车
  - 自取 / 配送
  - 地址与距离校验
  - 微信支付
  - 订单状态、配送状态、优惠券、会员积分
- 商家网站后台
  - 商品、价格、库存、营业时间
  - 订单、退款、会员、优惠券
  - 配送规则、利润保护规则
  - 成本中心与智能定价
  - 接单铃声自定义
  - 数据统计
- 商家接单工作台
  - 新订单实时弹窗与响铃
  - 接单 / 拒单 / 制作中 / 制作完成
  - 自动或手动呼叫骑手
- 配送
  - 第一批适配：顺丰同城 + 达达秒送
  - 同时询价、比价、自动选平台或人工选择
  - 预留美团配送适配器
- 成本与定价
  - 食材 BOM、损耗、采购价
  - 包装、人工、房租、水电等成本
  - 优惠券、支付手续费、配送费纳入订单成本
  - 贡献利润与全成本利润双口径
  - 最低安全价、建议售价、活动最低价
  - 不同配送距离与优惠组合的定价模拟
- 测试中心
  - 模拟下单、支付、接单、制作、骑手接单、取货、送达
  - 模拟异常：支付失败、骑手无人接单、配送接口超时、取消、退款失败
  - 测试模式可随时关闭；生产环境关闭后，后端禁止调用 Mock 接口

## 核心原则

1. **先预判再付款**：配送订单在用户付款前完成距离、配送费、优惠、成本和最低利润校验。
2. **不做赔钱单**：若预计订单利润低于后台设置的最低利润/最低毛利，系统不允许按原条件提交。
3. **允许用户补足**：如果订单仅因配送成本过高导致不达标，系统展示原因和需要补足的配送费；用户同意后重新报价并继续下单。
4. **超距离可直接禁配**：超过硬性最大配送距离时，系统可禁止配送，不允许用补差价绕过（后台可配置）。
5. **价格与配送报价都有有效期**：用户确认补差价后，提交订单前必须重新校验，避免骑手报价变化导致亏损。
6. **双利润口径**：实时接单主要看贡献利润；长期定价和经营分析看包含房租、人工等分摊后的全成本利润。
7. **支付、退款、配送回调必须幂等**：防止重复扣款、重复退款、重复叫骑手。
